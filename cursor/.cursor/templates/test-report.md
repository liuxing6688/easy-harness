> R32（`.cursor/harness/spec/mechanical-gates.md` §8.6，机读硬门禁）：跑 E2E 前须对 `detail-design-spec.md` §4「生产启动与异常恢复」声明的**生产启动命令**执行 `node .cursor/scripts/startup-smoke-run.mjs`，含两段：①**干净启动**（进程稳定存活 / 健康检查通过）；②**强杀后再启动**（覆盖陈旧锁、PID 残留、端口未释放等异常退出恢复）。机读产物 `test-results/e2e/.startup-smoke-result.json` 须 `gatePassed=true`，且批次与最终两级测试均校验。

## 存储对账记录

> R17（`.cursor/harness/spec/mechanical-gates.md` §8.3，机读硬门禁）：**开发窗口批次集成测试阶段**须满足 `batchStorageReconPresent`（`checkBatchStorageReconciliationReport`）。本章节须含真实数据行；**场景类型**在未豁免 R14 时至少一行「接口」/API **且介质非「不适用」**，未豁免 E2E 时至少一行「E2E」/UI **且介质非「不适用」**；项目未整体豁免时**至少一条适用（真实对账）行**。每行**关联任务包 / 对账方式 / 预期存储结果 / 实际存储结果 / 是否通过**须非空；**适用行的「对账方式」须包含证据路径** `test-results/recon/<name>.json`（文件须存在，JSON 含非空 `command`/`summary` 与数值 `exitCode`，由测试工程师实际查验后落盘；「不适用」行不要求证据）。**存储介质**须为可识别类别（数据库 / 文件 / 缓存 / 对象存储 / 其他 / 不适用）；介质为「其他」时**备注**须写明具体系统；介质为「不适用」时**备注**须说明该任务包无业务数据写入的理由。进度列表中已完成批次测试的任务包编号须全部出现在「关联任务包」列。**不得**仅靠「不适用」行代替真实对账或项目级豁免。缺证据路径/文件 → stop 门禁 R17 followup。无业务数据持久化可走双要素豁免。查验语义正确性仍由 QE/PM 审查（§8.4）。
